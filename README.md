📊 STATIFY

A reliable, statistics data analysis application.

Statify is a Python and Streamlit-based statistical analysis application designed to make data analysis more accessible while keeping statistical computation deterministic, transparent, and verifiable.

The project aims to bridge the gap between a raw dataset and meaningful statistical analysis by helping users understand their data, identify suitable statistical procedures, perform the required calculations, and interpret the results.

«Core principle: AI may help explain statistics, but the statistical calculations themselves should come from verified, deterministic statistical methods.»

---

📌 Overview

Performing statistical analysis is not simply about calculating a number.

A reliable analysis requires several decisions before a statistical test is performed:

- What type of data is being analysed?
- What variables are available?
- Are the variables suitable for the intended analysis?
- Which statistical method is appropriate?
- Are the assumptions of that method satisfied?
- What does the resulting statistic and p-value actually mean?

Statify is being developed around this complete workflow.

Instead of treating statistical analysis as a collection of independent buttons and calculations, Statify is designed as a structured statistical decision and analysis system.

---

🎯 Why Statify?

Many statistical tools focus primarily on computation:

«Select a test → enter data → get a result.»

However, this can create a major problem for beginners and inexperienced users: getting a mathematically correct calculation does not necessarily mean performing a statistically appropriate analysis.

Statify aims to address this by introducing checks and reasoning before the final calculation.

The long-term goal is to allow a user to move from:

Raw Dataset
     ↓
Understanding the Data
     ↓
Checking Data Readiness
     ↓
Identifying Suitable Methods
     ↓
Checking Assumptions
     ↓
Performing Statistical Analysis
     ↓
Verifying Results
     ↓
Understanding the Results

🚀 Project Origin

Statify originated from the idea of creating a practical statistical application that could help students and other users perform statistical analysis without turning the application into a simple collection of statistical formulas.

The initial concept was straightforward:

«Upload a dataset and perform statistical analysis through a single application.»

As the project developed, the scope evolved.

The focus shifted from simply adding more statistical tests to designing a system that understands the relationship between the dataset, statistical assumptions, appropriate methods, calculations, and interpretation.

This led to the current architecture of Statify.

The project therefore focuses not only on:

"Can we calculate this?"

but also on:

"Should we calculate this, and under what conditions?"

🧠 Core Philosophy

Statify follows several important design principles.

1. Deterministic statistical computation

Statistical calculations should be performed using established mathematical and statistical procedures rather than generated by an AI model.

For example:

Dataset
   ↓
Statistical Function
   ↓
Calculated Statistic
   ↓
Verified Result

The result should be reproducible when the same valid input is provided.

---

2. AI should not invent statistical results

AI can be useful for:

- explaining statistical concepts
- translating technical results into simpler language
- generating interpretations from verified results
- answering questions about an already-computed analysis
- helping users understand statistical terminology

However, AI should not be responsible for independently calculating statistical values.

The intended architecture is therefore:

Data
 ↓
Deterministic Statistical Engine
 ↓
Verified Statistical Result
 ↓
AI Narrator
 ↓
Human-readable Explanation

rather than:

Data
 ↓
LLM
 ↓
Statistical Answer

---

3. Recommendation should be rule-based

Statistical recommendations should be based on explicit statistical rules and data characteristics wherever possible.

For example, the recommendation system may consider:

- variable type
- number of variables
- number of groups
- paired/unpaired structure
- categorical/numerical variables
- sample characteristics
- assumptions
- purpose of analysis

This makes the recommendation process more transparent and auditable.

---

4. Verification before interpretation

A result should be verified before it reaches the interpretation layer.

Calculation
    ↓
Validation
    ↓
Verified Result
    ↓
Interpretation

This reduces the possibility of an explanation being generated from an invalid or incomplete calculation.

🔍 Architecture Components

1. Dataset Upload

The user begins by providing a dataset to Statify.

The application then examines the dataset before any statistical procedure is attempted.

The objective is to establish what the data actually contains rather than making assumptions about it.

---

2. Data Profiler

The profiler is responsible for understanding the structure of the dataset.

Potential information includes:

- number of observations
- number of variables
- variable names
- data types
- missing values
- unique values
- categorical variables
- numerical variables
- basic descriptive statistics
- potential data-quality issues

This information becomes the foundation for later decisions.

---

3. Validator

The validator checks whether the dataset is suitable for a particular operation.

Instead of allowing every statistical function to run on every dataset, Statify is designed to introduce validation before analysis.

Conceptually:

Input
  ↓
Is the input valid?
  ↓
Are the required variables present?
  ↓
Are their types appropriate?
  ↓
Is the required structure available?
  ↓
Proceed / Reject / Request correction

---

4. Readiness Checks

Before performing an analysis, Statify can determine whether the dataset satisfies the basic requirements necessary for the selected procedure.

This layer acts as a bridge between:

data validation

and

statistical analysis.

---

5. Rule-Based Recommendation Engine

The recommendation layer is intended to help determine which statistical procedures may be appropriate.

Rather than asking an AI model to guess the correct statistical test, Statify uses structured rules.

A simplified example:

Variable Type
      +
Number of Groups
      +
Study Structure
      +
Analysis Objective
      +
Assumptions
      ↓
Candidate Statistical Methods

This makes the recommendation process more explainable.

---

6. Assumption Checking

Statistical tests often rely on assumptions.

Depending on the procedure, these may involve conditions such as:

- normality
- independence
- equal variance
- distributional assumptions
- sample structure

Statify is designed to treat assumption checking as an explicit part of the workflow rather than an afterthought.

---

7. Deterministic Statistical Engine

This is one of the most important components of Statify.

The statistical engine performs the actual mathematical/statistical calculations using established computational methods.

The engine should produce structured results rather than unstructured text.

For example:

Test
Statistic
Degrees of Freedom
P-value
Effect Size
Confidence Interval
Decision

where applicable.

The output then becomes an input to the verification and interpretation layers.

---

🤖 AI Layer

AI is treated as an interpretation and interaction layer, not as the statistical calculator.

AI may be used for:

- explaining results
- simplifying statistical terminology
- generating natural-language interpretations
- answering questions about computed results
- providing contextual explanations
- assisting users in understanding statistical concepts

AI should not:

- fabricate statistical values
- independently calculate critical statistics
- replace deterministic statistical functions
- silently modify computed results
- make unsupported claims from incomplete data

The intended principle is:

«Calculate first. Verify second. Explain third.»

---

🛡️ Reliability Model

Statify is designed around a separation of responsibilities.

Component| Primary Responsibility
Data Profiler| Understand dataset structure
Validator| Check input validity
Recommendation Engine| Suggest suitable methods
Assumption Layer| Check statistical conditions
Statistical Engine| Perform calculations
Verification Layer| Validate generated results
AI Narrator| Explain verified results
User| Make the final analytical judgment

This separation is intended to reduce the risk of an AI system becoming a hidden source of statistical calculations.

⚙️ Installation

Clone the repository:

git clone https://github.com/LordRipon-begin/statify.git

Move into the project directory:

cd statify

Create a virtual environment:

python -m venv venv

Activate it.

Windows

venv\Scripts\activate

macOS / Linux

source venv/bin/activate

Install dependencies:

pip install -r requirements.txt

Run the application:

streamlit run app.py

The application will then be available through the local Streamlit server.

🔬 Design Goal

Statify is not intended to become simply another collection of statistical calculators.

The larger goal is to create a system that encourages statistically responsible analysis.

A user should not only receive:

«"p = 0.032"»

but should be able to understand:

- What test was used?
- Why was this test selected?
- What assumptions were considered?
- What does the statistic represent?
- What does the p-value mean?
- What conclusion can reasonably be drawn?
- What limitations should be considered?

This is the direction in which Statify is being developed.

---

⚠️ Limitations

Statify is currently a developing project and should not be treated as a replacement for professional statistical software or expert statistical consultation.

Automated recommendations can only be as reliable as the rules and information available to the system.

Statistical conclusions also require domain knowledge and an understanding of the study design.

Therefore:

«Statify is intended to assist statistical analysis, not replace statistical judgment.»
